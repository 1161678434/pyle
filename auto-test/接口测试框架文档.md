## 一、框架总览

### 1.1 目录结构

```
D:\pyle\
│
├── config/                          ← 【配置层】环境切换、超时设置
│   ├── __init__.py                  ← 让 Python 识别为包
│   └── settings.py                  ← Dev / Staging / Prod 三套配置
│
├── conftest.py                      ← 【Fixture 层】pytest 自动加载
│   ├── base_url       (session)     ← 从 config 读取 URL
│   ├── login_token    (function)    ← 每个用例重新登录，返回 token
│   ├── auth_headers   (function)    ← token 拼成 Authorization 头
│   └── api_session    (function)    ← 已登录 Session，最常用
│
├── reports/                         ← 【报告输出】
│   ├── test_report.xml              ← junitxml 格式（CI 集成用）
│   └── *.json                       ← allure 数据文件
│
├── api_test_server.py               ← 【Mock 服务器】本地 Flask 测试目标
│
├── api_day1_http_basics.py          ← 【测试用例】HTTP 基础
├── api_day2_pytest_requests.py      ← 【测试用例】pytest + requests 整合
├── api_day3_fixture_data.py         ← 【测试用例】fixture 管理数据
└── api_day4_framework.py            ← 【测试用例】框架集成 + allure
```

### 1.2 三层分离架构

```
┌─────────────┐     ┌─────────────┐     ┌─────────────┐
│  配置层      │ ──→ │  Fixture 层  │ ──→ │  用例层      │
│  config/     │     │  conftest.py │     │  test_*.py   │
├─────────────┤     ├─────────────┤     ├─────────────┤
│ "跑哪个环境"  │     │ "怎么登录"    │     │ "测什么"      │
│ BASE_URL     │     │ "怎么拿token" │     │ "断什么"      │
│ TIMEOUT      │     │ "怎么关连接"  │     │               │
└─────────────┘     └─────────────┘     └─────────────┘
```

换一个环境：改配置，不动 fixture，不动用例。
换一个接口：改用例，配置和 fixture 不变。

## 二、配置层详解（config/settings.py）

### 2.1 设计思路

```python
class Config:
    TIMEOUT = 10          # 所有环境共享

class DevConfig(Config):
    BASE_URL = "http://127.0.0.1:5000"

class StagingConfig(Config):
    BASE_URL = "http://staging-api.example.com"

class ProdConfig(Config):
    BASE_URL = "http://api.example.com"
```

继承：子类自动拥有父类的 `TIMEOUT`，只定义差异项。

### 2.2 切换环境（三种方式）

| 方式 | 命令 | 适用场景 |
|------|------|----------|
| 默认 | `get_config()` | 本地开发 |
| 代码指定 | `get_config("staging")` | 临时切换 |
| 环境变量 | `set TEST_ENV=prod` | CI/CD 流水线 |

### 2.3 为什么不用硬编码？

```python
# ❌ 硬编码：换环境要改 50 个文件
resp = requests.get("http://127.0.0.1:5000/api/user")

# ✅ 配置分离：改一行，全局生效
resp = requests.get(f"{base_url}/api/user")
```

## 三、Fixture 层详解（conftest.py）

### 3.1 fixture 依赖链

```
base_url (session 级，只执行 1 次)
    │
    └──→ login_token (function 级，每个用例重新登录)
              │
              ├──→ auth_headers ──→ {"Authorization": "Bearer xxx"}
              │
              └──→ api_session ──→ 已登录的 requests.Session
                   ├── 自动管理 Cookie
                   ├── 自动携带 Authorization
                   └── 测试结束自动 s.close()
```

### 3.2 作用域速查

| scope | 执行次数 | 适合放 | 不适合放 |
|-------|---------|--------|----------|
| session | 1 次/测试会话 | base_url、API key | token |
| module | 1 次/.py 文件 | 模块级共享数据 | 会变化的值 |
| function | 1 次/测试函数 | token、测试数据 | 不变的大资源 |

### 3.3 yield 执行顺序

```python
@pytest.fixture
def api_session(base_url, login_token):
    s = requests.Session()              # ① setup：测试前执行
    s.headers.update({...})
    yield s                             # ② 暂停，把 s 交给测试函数
    s.close()                           # ③ teardown：测试后执行
```

## 四、用例层写法规范

### 4.1 标准用例模板

```python
@allure.feature("模块名")        # allure 报告的大分类
class TestXxxAPI:

    @allure.story("子功能")       # 子分类
    @allure.title("用例一句话描述") # 报告里的用例名
    def test_xxx(self, base_url, api_session):
        """
        Given: 前置条件（fixture 已处理）
        When:  执行的操作
        Then:  预期的结果
        """
        # Arrange（fixture 已准备，这里只需 Act + Assert）
        resp = api_session.get(f"{base_url}/xxx")

        # Assert
        assert resp.status_code == 200
        assert resp.json()["field"] == "expected"

    # 反例：验证"不该成功的情况"
    def test_xxx_unauthorized(self, base_url):
        resp = requests.get(f"{base_url}/xxx")  # 不带 token
        assert resp.status_code == 401
```

### 4.2 断言三板斧

```python
# 1. 断言状态码
assert resp.status_code == 200

# 2. 断言响应头
assert "application/json" in resp.headers["Content-Type"]

# 3. 断言响应体
data = resp.json()
assert data["name"] == "expected"
assert "required_field" in data
```

## 五、报告体系

### 5.1 allure 报告（可视化）

```bash
# 生成报告数据
pytest api_day4_framework.py -v --alluredir=reports

# 浏览器打开
allure serve reports
```

**allure 装饰器四大件：**

| 装饰器 | 作用 | 位置 |
|--------|------|------|
| `@allure.feature("用户管理")` | 大类分组 | class 头上 |
| `@allure.story("创建用户")` | 子分组 | def 头上 |
| `@allure.title("POST 创建")` | 重命名用例 | def 头上 |
| `with allure.step("发送请求"):` | 步骤标记 | 函数体内 |

### 5.2 junitxml 报告（CI 集成用）

```bash
pytest test_*.py --junitxml=reports/test_report.xml
```

标准 XML 格式，Jenkins / GitHub Actions 直接读取。

### 5.3 pytest 原生输出

```bash
pytest -v              # 一行一条用例
pytest -v -s           # 加上 print 输出
pytest --tb=short      # 失败时精简 traceback
```

## 六、从 0 开始的调用链路（一次完整请求）

以 `test_valid_token` 为例，追踪一次调用：

```
1. pytest 发现 test_valid_token(base_url, api_session)
       │
2. 解析依赖：api_session 需要 base_url + login_token
       │
3. 先执行 base_url（session 级，可能已缓存）
       ├── config/settings.py → DevConfig → "http://127.0.0.1:5000"
       │
4. 再执行 login_token（function 级，每次新登）
       ├── POST http://127.0.0.1:5000/api/login
       ├── {"username": "qa_tester", "password": "test123"}
       ├── 返回 token: "eyJhbGci..."
       │
5. 最后执行 api_session
       ├── s = requests.Session()
       ├── s.headers.update({"Authorization": "Bearer eyJhbGci..."})
       ├── yield s ─────────→ 交给测试函数
       │                              │
       │                    test_valid_token 运行：
       │                      api_session.get("/api/user/profile")
       │                                │
       │                      assert resp.status_code == 200
       │                                │
       ├── s.close() ←────────────── 测试结束
       └── print("Session 已关闭")
```

**测试函数只需写 3 行代码**，URL、token、Cookie 全由框架处理。

## 七、环境切换实战

```bash

pytest api_day4_framework.py -v

# 切到 staging（临时）
pytest -c /dev/null --override-ini="addopts=" -v -s

$env:TEST_ENV="prod"; pytest test_*.py -v --junitxml=reports/junit.xml --alluredir=reports
```
