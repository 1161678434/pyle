# 调试笔记：如何快速定位 bug

## 一、四类最常见 bug 速查

| 类型 | 错误信息关键词 | 一眼定位法 |
|------|---------------|-----------|
| NameError | `name 'xxx' is not defined` | Cmd/Ctrl+F 搜变量名，看定义处写对了没 |
| KeyError | `KeyError: 'xxx'` | 在报错行加 `print(list(dict.keys()))`，对比实际 key 名 |
| 逻辑错误 | 无报错但结果不对 | 在关键变量变化处加 `print()`，追踪它怎么被改动的 |
| 语法错误 | `SyntaxError` | Python 会直接标出行号，看那一行的 `=`/`:`/括号 |

## 二、调试流程口诀

```
1. 看报错行    → 报错信息已经告诉你文件和行号
2. 往前找源头  → 报错行通常是"受害者"，往前 3-5 行才是"凶手"
3. 加 print    → 在嫌疑位置打印变量值和类型
4. 形成假设    → "如果 x 是 None，这里就会崩"
5. 验证        → 再跑一次确认
```

## 三、万能 print 模板

```python
print(f"[DEBUG] 变量名 = {变量}, type = {type(变量)}")
```

加 `type()` 是重点——很多时候 bug 不是值不对，是类型不对（比如 `"3"` vs `3`）。

## 四、调试优先级

```
报错信息能定位  → 90% 的 bug，直接看 traceback
加 1-2 行 print → 剩下 9%
断点/单步调试    → 最后 1%，复杂逻辑才用
```

**原则：能靠报错定位的不加 print，能靠一行 print 的不上断点。**

## 五、常见陷阱速记

- KeyError：你写的 key 名和数据里的不一致（多字母、少字母、大小写）
- 变量拼写错：IDE 里没标黄只是因为它恰好是另一个存在的变量
- 初始值反了：默认 True 和默认 False 搞混——想清楚"假定通过"还是"假定失败"
- 上游返回 A，下游读 B：两个函数的数据约定不一致，统一字段名
